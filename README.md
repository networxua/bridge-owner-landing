# Bridge — сторінка для власників і вітрина обʼєктів

Презентаційна версія окремого сайту Bridge. Не каталог з цінами і не сторінка «купити в ЖК». Власник бачить, як виглядає упаковка квартир, і шлях своєї: оцінка → план → упаковка → канали → покази → щотижневий звіт.

Статичний корінь: `index.html`, `listings/index.html`, `assets/`. Збірки немає. Готово до GitHub Pages.

## Що на сторінці

- Перший екран: фото вітальні з видом на місто і вибір «оцінка / обʼєкти». Форми на герої немає.
- Шість кадрів з портфоліо Bridge. Підпис описує те, що видно. Району, площі, ціни і статусу немає: у CMS клієнта цих полів не було.
- `listings/` — той самий список, без окремих сторінок квартир. Деталь `listings/{slug}/` зʼявляється лише з підтвердженим записом.
- Кейс — цикл роботи, без суми і без строку угоди.
- Звіт — файл `assets/10_weekly_report_structure_mock.png`, підпис «Приклад структури звіту». Цифр тижня там немає.
- Форма нічого не відправляє. Після натискання лишається текст, що це превʼю.

## Чого на сторінці навмисно немає

Публічні тексти чинного сайту Bridge не фіксують безкоштовну оцінку і відповідь у день звернення. Ці формулювання зі стратегії на сторінку не перенесені. Відсоток комісії і стаж команди теж не стоять: для першого екрана вони не потрібні, а «зазвичай 5%» і «7 років» легко читаються як обіцянка.

Не перенесені шаблонні цифри чинного сайту (300%, 5k+, $100m, 10k+) і суми угод.

## GitHub Pages

Статичний корінь, без Actions і без секретів. Файл `.nojekyll` уже в корені.

GitHub API відповів `403 Resource not accessible by integration` — токен не може вмикати Pages. Секрети не потрібні. Увімкнути вручну:

1. Відкрити https://github.com/networxua/bridge-owner-landing/settings/pages
2. Build and deployment → Source: **Deploy from a branch**.
3. Branch: `cursor/bridge-owner-v1-3cea` (після злиття в `main` перемкнути джерело на `main`).
4. Folder: `/ (root)`.
5. Save. За хвилину сайт буде на https://networxua.github.io/bridge-owner-landing/

Окремий workflow не додавати. Посилання в коді відносні (`listings/`), щоб працювали і локально, і на адресі репозиторія.

## Що потрібно для публічного каталогу

- Підтверджені поля на кожне фото: назва, район або адреса (якщо можна показати), кімнати, м², ціна, статус.
- Право публікувати ці кадри поза внутрішньою презентацією.
- Згода на цифри кейсу, якщо вони зʼявляться.
- Реальний щотижневий звіт замість структурного макета.
- Куди підключати форму. Аналітику і піксель не ставити до окремого рішення.
- Чи показувати портрети команди. Зараз імена є, фото людей немає.
